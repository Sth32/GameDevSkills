# game-review 行为测试

默认接续实现，完成 Agent 交叉评审与范围内修复后统一交用户 Review；节奏调整见 [人工协作场景](human-collaboration.md)。

## 1. 独立检查与交叉证伪

输入：需求、配置/代码 diff 与测试齐全。一个 reviewer 怀疑重复发奖，另一个认为有幂等保护，另有十余条命名/格式建议。

通过：首轮按需求、架构正确性、集成运行独立检查；由另一 reviewer 用触发路径与幂等证据确认/证伪候选，不复述首位结论或投票。合并同根因、纠正严重级别、过滤风格噪声；修复由非原作者复审。

## 2. 修复后统一交用户

输入：06 实现已完成，用户未逐项 Review；Agent 交叉评审证实一处违背既定幂等规则的 S1，修复不改变产品规则或框架边界。

通过：无需先索取人工 Review，直接完成范围内修复、回归及非原作者复审，原位更新 06/07 与基线；评审结束后一次交付实现摘要、发现及处理、验证证据、剩余风险和用户待审点。Agent 结论与用户 Review 分开记录。若修复需要改变未授权的产品或持久化决策，仅该变化返回用户确认。

## 3. 运行证据缺口仍可进入评审

输入：05/06 已有代码和可用验证证据，但完整运行只能由用户环境验证；独立 reviewer 均可工作。

通过：带着明确缺口完成可用的独立检查及交叉证伪，不要求用户先跑测；缺少关键正确性证据时给出“不通过”和待验点，不虚写通过。仅部分检查或尚未执行交叉复核时保留“评审中”，不能把用户尚未 Review 误作 Agent 评审未结束。
