# 分支工作流行为评估

路径与跨天续接见 [文档位置场景](document-location.md)。所有工作单元文件同目录。

| 场景 | 输入 | 通过标准 |
|---|---|---|
| 1. 简单单线 | 范围紧凑，无独立推进需求 | 使用 01–07 原名，不创建 00/Uxx |
| 2. 从 01 拆分 | 战斗、奖励可由两人独立推进 | 建 00、`U01-01-战斗-原始需求.md`、`U02-01-奖励-原始需求.md`；共享 01 只留共同规则，专属事实移动不复制；叶 01 完成可独立进 02，不等整体 01 完成 |
| 3. 兄弟独立 | U01 在 06，U02 在 03，无依赖 | U01 可实现、对接，满足自身门禁后进 U01-07，不等 U02 |
| 4. DAG | U03 依赖 U01/U02 | 等真实前驱所需稳定状态；ID 不编码拓扑（如 U01.1），改依赖不重命名 |
| 5. Step | U01 需三次人工 Review，却不能独立交付 | 一份 U01-06 内用 Step 1/2/3，不制造 U02/U03 |
| 6. 分支对接 | U01/U02 合同不同 | 各用 `Uxx-06-<主题>-客户端对接文档.md`，共享合同引用；本单元合同稳定即可生成，06 仅排序，骨架阶段也可对接 |
| 7. 单分支 Review | U01 实现/合同就绪，U02 仍实现且无依赖 | 完成 U01-07，不用整体 07 冒充全部完成，不强制汇合 |
| 8. Review 再拆分 | U01 中发现独立生命周期 | 暂停受影响 Review，回最早合适阶段建新 Uxx，新叶分别 Review；无关通过状态不失效 |
| 9. 整体集成 | U01/U02 各通过但共享数据/客户端协议 | 建整体 07，先读分支 Review/对接，检查共享事实、协议、时序、覆盖和 Review 后漂移，不重做内部检查 |
| 10. 无集成耦合 | 各 Uxx 无共享代码/数据/协议/配置/发布耦合 | 00 写整体 Review 不需要；长期文档读全部分支 Review 与代码，不因缺整体 07 阻塞 |
| 11. 无单一 01 | 00 有 U01-01 已完成、无依赖 U02-01 待确认，无共享规则/单一 01；用 discovery 模板处理 U01 | 创建 U01-02、链接 U01 基线，不补单一 01/不等 U02；若补入已拆分父 01 只核适用共享事实，不强改整理完成。后续 03 同样适用 |
| 12. 模板连续交付 | U01 的 01–06/合同就绪，U02 仍 03 且无依赖；用 implement 模板收尾 | 接力指 U01-07，可立即 Review，不补整体 07；各分支通过且无集成风险后可生成长期文档，正文/模板不得重引汇合门禁 |
| 13. 排序 | 同目录含 U01/U02 各阶段、配表、对接 | 分支号在前、阶段号在后，至少两位补零；配表 Uxx-04，对接 Uxx-06；00、整体07、功能08 不带 Uxx，不建子目录 |
| 14. 旧名 | 00 指向 `03-U01-战斗-程序实现澄清.md`，用户先要求续写、后明确统一命名 | 先原位续写；获明确要求后同目录改为 `U01-03-战斗-程序实现澄清.md` 并更新 00/引用，保留身份/状态，不造副本或报缺文件 |
