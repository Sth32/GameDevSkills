# game-docs 行为测试

默认无额外授权；节奏调整见 [人工协作场景](human-collaboration.md)。

## 1. 大量调研压成长期文档

输入：01–07 数百行，代码含多表、完整调用链、修复与排查记录；用户要长期文档。

通过：查当前代码确认权威、核心规则、持久化/同步；只留职责边界、稳定规则、数据、关键协作和少量修改约束。路径仅指唯一真源和主要入口，同事实一次，标最后核对版本/日期。不搬文件清单、逐函数链、伪代码、证据过程、空章节或评审报告。

## 2. 配置快照、TODO 与现状边界

输入：实现读可调数值，Review 有配置错误，代码有优化 TODO，跨区暂不支持。

通过：只写配置作用与消费入口，不写行号/资源/时长/耐久/概率等当前值；跨区不支持写为当前边界。错误、修复、TODO、延期和扩展计划留在代码/issue/Review，不进入长期文档，不把目标当现状。

## 3. 权威、持久化与镜像

输入：权威实体持久化部分字段，其他实体起服/运行时同步镜像，链接资格实时派生，客户端消费同步结果。

通过：说明权威/持久化范围、镜像来源/方向/时机、派生不重复持久化；多入口共享同一判定。客户端仅写服务端合同，不展开完整 Schema、默认值或内部表现；镜像不能成为独立权威，不能只写调用流程忽略恢复。

## 4. 完成不新增阶段状态

输入：两个目标 Uxx-07 均通过，00 写“整体 Review：不需要”，实现/合同/证据一致；使用长期文档模板。

通过：读取真实分支状态，不补整体 07；只写稳定契约、最后核对版本和权威入口，重读落盘后可完成，不加阶段状态、未决计数或步骤，也不因模板无终态阻塞。

对照：一分支改为“不通过”且有未决 S1，则回该 Review 解决，不能因长期文档无状态而跳过上游。
