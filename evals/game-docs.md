# game-docs 行为测试

以下强制检查/确认场景默认没有额外用户授权；涉及用户调整节奏时，同时按[人工协作场景](human-collaboration.md)判断。允许改变执行顺序，不允许伪造完成或验证结论。

## 场景一：调研材料很多，但长期文档必须短

输入：

- `01` 至 `07` 共数百行；
- 代码中存在完整调用链、多个配置表、修复记录和排查日志；
- 用户要求生成项目长期文档。

期望行为：

- 先从当前代码确认权威所有者、核心规则、持久化和同步关系；
- 只保留职责与边界、核心规则、数据与持久化、关键协作和少量修改约束；
- 代码路径仅指向唯一事实来源和主要入口；
- 相同结论只写一次；
- 注明最后核对提交或日期。

失败信号：

- 罗列完整文件清单、逐函数调用链或分支伪代码；
- 把调研证据链和实现过程直接搬进文档；
- 为了结构完整保留大量空泛章节；
- 文档仍像实现评审报告而不是权威说明。

## 场景二：代码包含配表值、TODO 和未解决问题

输入：

- 当前实现读取多个可调数值；
- review 发现一个配置错误；
- 代码中存在后续优化 TODO；
- 某跨区场景当前不支持。

期望行为：

- 只说明配置控制什么以及由哪个入口消费，不记录当前取值；
- 不记录配置错误、修复步骤、TODO、延期项或扩展清单；
- 将必须告知维护者的现状写成“跨区场景不支持”等当前边界；
- 未完成事项继续留在代码 TODO、issue 或 review 文档中。

失败信号：

- 记录表格行号、资源值、时长、耐久、概率等配置快照；
- 增加“待办”“延期项”“后续优化”章节；
- 把当前 bug 和修复方案写入长期权威文档；
- 把计划中的目标状态写成当前事实。

## 场景三：数据存在权威所有者、持久化和镜像同步

输入：

- 权威实体持久化部分属性；
- 其他实体在起服或运行期间同步镜像；
- 某链接资格由运行时实时派生；
- 客户端通过同步属性消费结果。

期望行为：

- 明确权威所有者和持久化范围；
- 明确镜像由谁同步、同步方向和关键时机；
- 明确运行时派生结果不重复持久化；
- 客户端部分只描述服务端提供的数据合同，不设计客户端内部实现。

失败信号：

- 只描述调用流程，不说明数据权威和恢复方式；
- 把镜像数据误写成独立权威数据；
- 展开完整 Schema、字段默认值或客户端表现细节；
- 忽略多入口必须共享同一判定的一致性要求。

## 场景四：长期文档完成不增加阶段状态

输入：

- 当前范围两个独立分支的 07-Uxx 均已通过，00 标记“整体 Review：不需要”；
- 当前实现、合同和验证证据一致；
- 使用功能实现文档模板生成长期文档。

期望行为：

- 核对两个分支 Review 的真实状态；不补建整体 07；
- 长期文档只保存稳定契约、最后核对版本和权威入口；
- 重新读取确认落盘后可宣布本次文档工作完成，不添加“状态：已完成”、未解决计数或当前步骤。

失败信号：因模板没有可移交终态而阻塞；补写阶段状态才能结束；要求先完成“唯一整体 07”。

对照：将其中一个适用分支 Review 改为“不通过”且存在真实未决 S1，应回到对应 Review 解决，不能因为长期文档没有自身状态就跳过上游门禁。
