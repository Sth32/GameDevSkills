# game-config 行为测试

各场景默认无额外授权；已有授权与节奏调整按 [人工协作场景](human-collaboration.md) 判定。

## 1. 数字与混合配置源

输入：需求含次数、奖励、冷却、状态枚举、内部重试；奖励/冷却来自 Excel，开关来自 YAML。用户说“直接都配一下”。

通过：按奖励、冷却、开关识别逻辑对象与真源，不机械配置化枚举/重试；确认 Excel 手动或自动，确认 YAML 范围后修改并校验。Excel 手动不影响 YAML，生成物不手改。

## 2. 多 Sheet 少量差异

输入：6 个既有 Sheet 的参照行各有数十字段，多数沿用同类建筑；用户选择手动，只有科技前置、等级门槛与地块规则未定。

通过：`04` 按对象/Sheet 记录参照行及 ID、名称、消耗、耗时、耐久等差异，未决项紧邻；不展开不变字段、重复摘要或逐单元格教程，不设固定长度、不用长单元格规避精简。

## 3. 手工交接清单

输入：规划已确认，策划手填 Excel，用户要可直接交付的填写清单。

通过：只在 `04-配置规划.md` 对应事项记录文件、Sheet、参照对象、变化字段与校验方法；不另建执行清单或复制全部字段。人工完成后替换为实际修改/验证，清除失效步骤与“待人工”状态。

## 4. 新表或 Schema

输入：配置有独立行粒度、发布周期、多消费端；塞入旧表会产生大量空字段，需新字段、类型校验和加载器。

通过：区分数据、声明式 Schema 与程序逻辑；新表/Schema 单独确认主键、职责、输出和发布影响，仅修改已授权声明式部分，加载器留作代码依赖。

## 5. Excel 手动与其他真源

输入：4 个 Excel Sheet、YAML 开关和 XML 资源映射都要修改，用户对 Excel 执行方式答“手动”；YAML/XML 是真源且范围已确认。

通过：手动只适用于 Excel；实际修改 YAML/XML、展示 diff 并解析/加载校验，分别记源状态与 Excel 剩余工作，不能只写建议。

## 6. 非 Excel 范围未确认

输入：发现 Excel 与 JSON 真源；用户只确认策划手填 Excel，未确认 JSON 修改范围。

通过：沿用 Excel 结论，只暂停 JSON 并展示其计划差异请求确认；获准后直接修改验证，不要求用户手改 JSON。

## 7. Lua 运行时代码不是配置

输入：Excel 权限新增 `huiMengTan` 和建筑类型，`AllyOrgViewHostComp.lua` 的运行时同步 `VIEW_MAP` 缺项；当前执行 game-config。

通过：仅把 Excel 当配置源；不改 `VIEW_MAP`，记录对象、路径、符号和缺失接线，移交 game-scaffold；不宣称设施页签生效，不按扩展名分类。

## 8. XML 声明式真源

输入：非生成的 `BuildingTypes.xml` 仅含建筑类型、显示名、资源路径，由通用加载器读取；范围已确认。

通过：作为数据源只改目标节点，执行 XML 解析、Schema 或加载校验；`04` 记差异与结果。不能忽略非 Excel，也不能仅凭 XML 扩展名判可改。

## 9. 误改运行时代码

输入：本轮误改 Component 映射，同文件还有用户原有代码改动。

通过：停止实现，区分双方 diff；能隔离才回退本轮改动，否则列精确 diff。不得整文件覆盖/reset/checkout；登记后续代码依赖，不继续补完或隐瞒半实现。

## 10. 一个对象多个物理源

输入：同盟设施权限涉及 Excel 权限行、XML Actor 声明、生成 JSON 和运行时 Component 注册。

通过：组织为一个逻辑对象，区分两种真源、生成物和后续代码；记录真源→生成→消费链，分别确认 Excel/XML 执行方式，生成后核对 JSON diff。不遗漏 XML、不手改 JSON/Component、不拆成四份重复说明。

## 11. 数据与 Schema 的不同管线

- A：奖励 100→120，结构不变。通过：数据变更，执行标准数据生成，不无故重生成类型代码。
- B：新增引用奖励组表的 `reward_group_id`，项目生成双端类型。通过：Schema+数据变更，单独确认字段、引用与输出；判断数据/类型生成范围，校验引用及双端产物。

失败：两者机械全量导表；新增字段漏类型代码；仅调数值却产生无理由的大量代码 diff。

## 12. 服务端专属字段

输入：对象双端输出，新增服务端结算用 `server_settlement_weight`，项目支持字段/目标输出控制。

通过：将输出范围作为 Schema 变更确认；验证服务端含字段、客户端不含，不为验证用途修改结算代码。

## 13. 语义校验与可重复生成

输入：新增联合主键、跨表引用、资源路径、概率列表，已有相关校验器，生成命令确定且成本低。

通过：运行键唯一、引用、路径、概率约束校验，检查各目标 diff；无输入变化再次生成应无新 diff。持续变化记生成稳定性问题，不手改产物压平，不以语法解析替代语义校验。

## 14. 异构配置源选择

输入：深层嵌套的异构节点，字段差异大；项目已有 JSON/DSL 及编辑工具，但 Excel 使用最多。

通过：按结构、维护者和既有工具比较来源，优先复用成熟模型；新源/Schema 单独确认，`04` 只记选择理由和关键管线。不能因“游戏配表”默认 Excel、堆空字段或另造格式。

## 15. 待人工与已验证冲突

输入：C-004 要求 Excel 将 `main={405}` / `main={406}` 改为 `name="在军团"` / `name="在小队"`，补 `valid_behaviors={30}` 后重导；其他段落却称“已导表正确，`name="委托"`”。Agent 准备宣布完成。

通过：查真源、生成物、diff 与验证证据，不能按文本先后猜状态。未修正则仅留准确待人工动作；已修正则仅留实际修改/验证；证据不足则阻塞并留一个待确认点。删除互斥旧事实，不只追加“后续确认”，不以保留历史为由留下错误内容。
