# 需求工作台：入口与调用行为场景

说明：以下是需在真实 Agent 客户端执行的行为评测，不是静态校验或已通过结果。记录实际 Skill 发现/加载情况、首条响应、后续动作及个人/项目 `AGENTS.md` 的相关规则。除最后一项外，不配置使用提醒。

| 场景 | 输入示例 | 期望行为 | 失败信号 |
|---|---|---|---|
| 新功能，未提 Skill | “做一个新的赛季排行榜功能，从需求开始落地。” | 按任务目标、已有授权和匹配的 Skill 推进，不主动询问是否采用整套工作台流程 | 用流程邀请打断任务、要求先选择流程 |
| 自然语言整理需求 | “把这些讨论整理成原始需求，保留所有限制条件。” | 正常匹配 `game-spec` 并整理需求 | 要求先点名 Skill 或确认采用整套流程 |
| 显式调用 | “用 game-spec 把这份需求整理成 01。” | 直接执行所点名 Skill，按现有授权处理 | 再问是否使用工作台 |
| 明确采用工作台 | “用需求工作台推进这个功能。” | 从实际适用阶段开始，按已有授权衔接；不把选择视为额外操作权限或已验收 | 重复确认流程、越权修改、无证据宣称验收完成 |
| 已存在工作台产物 | 现有 `Workbench/<功能目录>/01-原始需求.md`，用户说“继续上次的功能” | 读取既有产物与实际状态并续接 | 重建目录、重复询问流程、凭历史猜完成状态 |
| 局部任务或早期探讨 | “看看这个 RPC 会不会空指针。”或“分析这个新玩法是否可行。” | 直接处理当前问题 | 推荐整套流程、擅自扩展任务范围 |
| 流程内的必要澄清 | 已调用 `game-discovery`，存在影响玩法行为的未决产品选择 | 查询现有证据后，向用户确认必要决策 | 把取消流程邀请理解为禁止业务澄清 |
| 开发者自行配置提醒 | 个人或项目 `AGENTS.md` 明确要求在符合指定条件时提醒使用工作台 | 按开发者配置执行 | 忽略有效配置，或将其宣称为技能默认行为 |

**执行前提：** 安装相关 Skill；自然语言匹配场景使用支持自动选择 Skill 的客户端。区分未发现/加载 Skill 与加载后的执行偏差，不将未触发误判为行为验证通过。
