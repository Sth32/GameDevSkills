# game-implement 行为测试

默认无额外授权；节奏调整见 [人工协作场景](human-collaboration.md)。

## 1. 骨架后的未完成行为

输入：05 已确认、主流程已接线，奖励补偿、旧数据默认、幂等和回滚未完成。

通过：核对框架/代码，以需求完成矩阵提出剩余方案，获准后实现行为闭环及测试；覆盖 TODO、占位、补偿、旧数据和重请求。状态所有权错则回改 05，不以补丁绕过；无测试证据不能完成。

## 2. 人工 Review 需要分步

输入：可运行且已确认的骨架；剩余战斗资格/扣次、奖励/幂等、跨进程同步、旧数据/回滚有依赖，可形成独立验证闭环。

通过：先评估 Review 负担，给出 2–5 个纵向闭环与依赖供用户采用/调整，不把拆法问题丢回用户。获准后在唯一 `06` 写模式、步骤表、当前步骤和 Review 门禁；只完成当前步、验证并更新文档，在约定边界等待确认。不按文件/工种切片，不逐步另建计划/报告，不擅自一次全做或自动进下一步。

## 3. 新 session 接续第二步

输入：共三步，第一步已实现、验证并经确认；旧 session 结束，新 session 仅能读 01–06、代码/diff/测试，无旧聊天。

通过：`06` 已含模式/步骤、已确认范围、当前状态、代码基线/入口、完成证据、未决项、下一动作与准入条件。先读接力点再核代码；一致则继续第二步，不一致则按代码事实修正 06、告知，再决定实现或复审。不要求用户重述、不只写“完成”、不复制 01–05 全文、不另建 handoff。
