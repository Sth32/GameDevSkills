# 游戏模块权威文档

先读 [文档位置](references/文档位置.md)，查找已有同主题文档并原位更新；没有时在功能目录创建 `08-功能实现文档.md`，明确指定文件则使用该文件。`08` 仅排序，不增加阶段状态。用 [功能实现文档模板](references/功能实现文档模板.md)，同一模块只保留一份权威文档。

## 输入与取舍

生成前读 [Review 覆盖](references/Review覆盖.md)。存在 `00-工作流索引.md` 时用它定位相关叶单元，不能把分支拓扑当成长期文档结构。

- 事实优先级：当前可运行代码/属性/协议 → 已验证运行与测试 → 有效 Review → 实现方案 → `01` 已确认基线 → 未决讨论。方案冲突时记录真实实现，指出需修正的具体上游与拟修改内容；沿用已有授权回写。
- 只保留稳定且不记录就易破坏语义的职责、规则、权威所有者、持久化/镜像/派生关系、跨模块合同及不变量。同一事实只写一次，按最终系统语义组织。
- 不写配置快照、TODO、修复与评审过程、完整文件/调用链、普通代码细节、Uxx/DAG、阶段状态或任务进度。数字仅在协议、存档或兼容契约需要时保留；当前不支持的场景写成边界，不写未来计划。
- 配置写控制内容和稳定消费入口；客户端只写服务端合同。历史原因仅在仍约束未来修改时保留。

## 协作与更新

- **人工协作**：用户可调整 Review 和回写节奏，沿用已有授权。提前整理仅用已验证稳定事实写草稿；缺口、假设、待补项及复核点留在过程文档或交接说明，不写成长久权威结论。
- **文档更新**：默认同轮原位替换过时契约并告知路径；集中回写时说明未落盘内容。不另建 v2、FAQ 或补充说明竞争权威；重复长期文档合并必要契约后删除或废弃。
- **结构性变更**：同步真实受影响的上下游、客户端合同和 `00`，不扩散到无关分支。

## 完成条件

无待确认的上游修订阻塞才可完成；提前整理按人工约定交付草稿。以当前代码与验证证据检查契约一致性，确认职责、数据恢复/同步和关键协作无遗漏；未知内容留在过程材料。更新最后核对版本并重新读取确认落盘。长期文档不写阶段终态、未解决计数或当前步骤。
