# 完成游戏功能实现

开始或恢复前读取 [文档与分支规则](references/文档与分支规则.md)，核对当前单元实际 `01`–`05` 依赖、当前 `06` 与代码/diff。默认上游状态为 `01=整理完成`、`02/03=已收敛`、`04=已完成`、`05=骨架已完成`。

`05` 仅缺目标环境运行证据时，保留其待验证状态、风险与可用证据继续实现；不要求用户先 review 或跑测。已证实的安全问题或未决核心设计须先处理受影响部分。

使用 [完整实现方案模板](references/完整实现方案模板.md)，每单元仅一份 `06-完整实现方案.md` 或 `Uxx-06-<主题>-完整实现方案.md`；实现、验证、发布/回滚和接力点都在其中，不另建过程报告。代码、测试、迁移与日志是实际证据。

## 实现规则

- 对照需求标明已由骨架完成、本阶段实现、延期/范围外、外部承载或缺决策，沿既定框架补齐行为。骨架不能安全运行或需推翻核心边界时，在 `06` 记阻塞并说明上游修订；已有授权直接回写 `05`，否则确认后修复，不堆局部补丁。
- **真实消费链验证硬限制：** 编码和验收前读取 [真实消费链](references/真实消费链.md)，只追踪本功能实际经过的节点。定义存在、代码已写或局部测试通过不等于闭环；关键证据缺失保持未完成或显式风险。
- 默认连续完成当前范围，不因 diff 大、验证可分段或多轮执行主动拆 Step；仅用户明确要求分步实施时采用 Step。编码前及暂停/结束前读取 [实现与接力](references/分步与接力.md)，保留可脱离聊天恢复的接力点。
- **分支工作流硬限制：** 真实独立生命周期优先拆 Uxx，同一闭环连续推进；不为制造人工检查点机械拆分。新 Uxx 及依赖写入 `00-工作流索引.md`；父 `06` 标记 `已拆分`。子范围沿用已确认 `01`–`05` 时可从子 `06` 继续，否则退回最早受影响阶段。

## 协作与更新

- **人工协作**：在已授权范围内连续实现并续接 `game-review`，完成 Agent 交叉评审、修复和复审后统一交用户 review；不在 `05/06` 强求人工确认或跑测。用户明确限定阶段或要求分步、暂停时遵从；关键决策、范围或风险实质变化时才重新沟通。继续不等于验证通过，缺口、假设、待补与复核点留在当前文档，不增审批文件。
- **文档更新**：默认同轮原位替换计划和旧结论，记录实际实现、验证与接力点并告知路径；集中回写时交接未落盘内容。
- **结构性变更**：范围、状态、合同、数据权威、依赖或配置真源改变时，同步真实受影响的上下游、客户端合同及 `00`；上游修订先列明影响和拟改内容，已有授权直接执行。

## 验证与移交

完成当前范围内行为、危险占位清理，以及实际涉及的配置、权限、副作用、失败、兼容与回滚闭环；由 Agent 执行当前环境可用且与风险相关的验证。不能执行的验证写明原因、替代证据、风险和待验场景，不把跑测转成人工前置任务，不隐藏 P0/P1 风险。

核对文档与代码一致性；必要证据充分且无未决上游阻塞时，顶部写 `已完成`、更新日期并重读确认落盘。仅缺环境运行证据时保持 `实现中`，正文注明代码已落地及待验证项，仍直接进入本单元 `Uxx-07`（单线 `07`）检查现有产物；不虚报完成或等待用户先跑测。各目标叶单元分别评审后，按集成风险评估整体 Review；最终人工 review 由 `07` 统一交接。
