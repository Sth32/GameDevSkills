# 完成游戏功能实现

开始或恢复前读取 [文档与分支规则](references/文档与分支规则.md)，核对当前单元实际 `01`–`05` 依赖、当前 `06` 与代码/diff。默认上游状态为 `01=整理完成`、`02/03=已收敛`、`04=已完成`、`05=骨架已完成`；05 仅缺目标环境运行证据时，沿真实待验证状态继续。

使用 [完整实现方案模板](references/完整实现方案模板.md)，每单元仅一份 `06-完整实现方案.md` 或 `Uxx-06-<主题>-完整实现方案.md`；验证、发布/回滚、接力点及用户约定的 Step 都在其中，不另建过程报告。代码、测试、迁移与日志是实际证据。

## 实现规则

- 对照需求标明已由骨架完成、本阶段实现、延期/范围外、外部承载或缺决策，沿既定框架补齐行为。骨架不能安全运行或需推翻核心边界时，在 `06` 记阻塞并说明上游修订；已有授权直接回写 `05`，否则确认后修复，不堆局部补丁。
- **真实消费链验证硬限制：** 编码和验收前读取 [真实消费链](references/真实消费链.md)，只追踪本功能实际经过的节点。定义存在、代码已写或局部测试通过不等于闭环；关键证据缺失保持未完成或显式风险。
- 编码前及暂停/结束前读取 [分步与接力](references/分步与接力.md)，保留可脱离聊天恢复的接力点。
- **分支工作流硬限制：** 按上述参考中的条件询问分支或 Step，仅按用户确认的方案拆分。创建 Uxx 时将范围及依赖写入 `00-工作流索引.md`，父 `06` 标记 `已拆分`。子范围沿用已确认 `01`–`05` 时可从子 `06` 继续，否则退回最早受影响阶段。

## 协作与更新

- **人工协作**：在已有授权内连续实现、验证并续接 `game-review`，不默认等待用户 Review 或跑测；用户限定阶段、分批 Review 或暂停时遵从。缺口、假设、待补与复核点留在当前文档，继续不等于验证通过。
- **文档更新**：默认同轮原位替换计划和旧结论，记录实际实现、验证与接力点并告知路径；集中回写时交接未落盘内容。
- **结构性变更**：范围、状态、合同、数据权威、依赖或配置真源改变时，同步真实受影响的上下游、客户端合同及 `00`；上游修订先列明影响和拟改内容，已有授权直接执行。

## 完成条件

已确认行为均实现或有外部承载，用户约定的 Step 已完成，危险占位清除；实际涉及的配置、权限、副作用、失败、兼容与回滚闭环，必要测试和运行验证通过。不能执行的验证写明原因、替代证据和风险；仅缺目标环境运行证据时保留未完成状态，仍进入 `07` 检查现有产物；实际安全问题或未决核心设计先处理，不以风险清单代替完成证据。不隐藏 P0/P1 风险。

核对文档与代码一致性；仅上述条件满足且无未决上游阻塞时，顶部写 `已完成`、更新进度与日期并重读确认落盘。直接续接本单元 `Uxx-07`（单线 `07`）正式 Review；Step 人工 review 不替代交叉 Review，各目标叶单元完成评审后，按集成风险评估整体 Review。
