# 实现接力

- 默认连续实现；用户选择分批 Review 时，才在同一 `06` 记录 Step 与检查点。每步为纵向行为闭环；跨单元依赖只记在 `00`。
- 补齐规则、配置/数据、失败与副作用边界，清理危险占位并验证；仅在用户约定的 review 点暂停，范围/风险/假设实质变化时再沟通。
- 编码前、review 边界及暂停/结束前，`06` 必须能独立回答：工作单元、当前进度与确认范围、实际代码基线/入口、已完成行为及证据、有效偏差/阻塞、下一动作和进入条件；只引用上游，不复制全文。
- 恢复时先核对接力点与实际代码/diff，不一致则据代码事实修正文档并告知用户，再决定继续或重做 review，不依赖旧聊天。
- 实现后用实际结果替换计划、清除失效风险，直接续接本单元 `07`；保留真实延期项及未覆盖验证。
