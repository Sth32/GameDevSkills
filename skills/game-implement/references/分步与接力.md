# 连续实现与接力

- 默认连续实现，不创建 Step 计划或步骤表；仅用户明确要求分步时，才按纵向行为闭环在同一 `06` 记录 Step，并沿用其检查点约定。真实独立范围优先拆 Uxx，跨单元依赖只记在 `00`。
- 补齐规则、配置/数据、失败与副作用边界，清理危险占位并完成可执行验证；不把内部任务完成或阶段切换变成用户审批点。
- 编码前及暂停/结束前，`06` 必须能独立回答：工作单元、当前范围与进度、实际代码基线/入口、已完成行为及证据、有效偏差/阻塞、下一动作和进入条件；只引用上游，不复制全文。分步信息仅在用户要求时保留。
- 恢复时先核对接力点与实际代码/diff，不一致则据代码事实修正文档并告知用户，再决定继续或重做 review，不依赖旧聊天。
- 实现落地后用实际结果替换计划、清除失效风险，直接续接本单元 `07` Agent 交叉 Review、修复与复审，最后统一交用户 review；保留真实延期项及未覆盖验证。只有明确的阶段限制、暂停约定或实际阻塞才停止接续。
