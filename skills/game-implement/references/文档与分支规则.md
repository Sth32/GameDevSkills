# 文档与分支规则

## 文档位置

- 先按已有文档、阶段引用或 `00` 找到同功能目录；所有阶段及 Uxx 在原目录续接，跨天或配置变化不另建。多个候选权威目录无法判定时澄清；仅明确要求迁移或统一旧名时移动、重命名并更新引用，不保留副本。
- 新建根目录按“本次指定 → 目标项目根目录 `.game-dev-workbench.json` 的 `documentRoot` → `Workbench`”选择。目标项目不等于技能安装目录或任意当前目录，不明确时澄清。
- 新建功能目录为 `<文档根目录>/<YYMMDD><功能名>/`；日期取首次建档的用户当地日期，不加分类或分支子目录。指定功能路径或带日期目录名时原样使用，不重复拼接。
- 配置仅执行本技能时按需读取；文件或字段缺失用默认值。`documentRoot` 须为非空相对路径字符串；需读取的配置无效时说明并停止依赖它的新建写入，不静默回退。不自动创建或改写配置，不读环境变量或个人配置，不写入 AGENTS.md。

## 工作单元

- 默认连续推进。仅在 `05/06` 内容精简后仍有大量复杂设计或行为需要逐项核对，明显难以一次集中 Review 时，才一次询问是否需要通过分支（Uxx）或分批（Step）参与本阶段 Review。普通多模块、大 diff 或内部任务多不触发。
- 用户选择后才拆分，按约定检查点暂停；不参与或未选择拆分时按现有范围继续，已表达的选择不重复询问。独立范围用 Uxx，同一闭环的分批 Review 用文档内 Step。
- 首次创建 Uxx 分支时建立 `00-工作流索引.md`，只存 ID、范围、依赖、当前阶段/文档及整体 Review 指针。稳定 ID 不编码拓扑；仅路由变化时更新，不复制业务事实或阶段状态。
- 分支文件为 `<Uxx>-<阶段号>-<主题>-<阶段名>.md`，编号至少两位补零。按实际引用续写旧名；单线保持原名，不创建 `00`。
- 拆出 Uxx 时分配新 ID，专属事实移入子文档，共享事实留在父文档供引用；父文档标记 `已拆分` 并停止推进，由叶后继继续。
- 开始或恢复时读取当前单元的共享基线、自身/祖先需求和真实前驱状态与证据，不等待无依赖兄弟。共享 `01` 的 `已拆分` 不是子单元完成，也不阻塞已完成的叶单元。
- 各叶单元可独立对接和进入 `Uxx-07-<主题>-交叉评审.md`；所有目标叶单元完成评审后，按集成风险决定整体 `07-交叉评审.md`，保留未通过结论及证据缺口。
