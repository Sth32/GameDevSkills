# 澄清游戏程序实现

开始时读取 [文档位置](references/文档位置.md)，按 [程序实现澄清模板](references/程序实现澄清模板.md) 维护 `03-程序实现澄清.md`。

**分支工作流硬限制：** 存在 `00-工作流索引.md` 或用户要求拆分时，先读 [分支规则](references/分支规则.md)。仅检查本单元真实依赖，不等兄弟分支汇合。

## 澄清范围

- 读取适用 `01`、`02` 与代码证据；默认叶需求 `整理完成`、实际依赖 `02` `已收敛`。缺口先返回上游；已有继续约定按约定推进。
- 影响实现方向的 P0/P1 产品问题先在 `03` 记最小阻塞并指回对应 `01/02`；不以技术默认值决定产品语义。可继续独立调查，不展开依赖未决答案的技术决定。
- 只问代码与约定不能回答、当前单元中必须由负责程序决定的高影响事项：架构/公共合同、持久化与迁移、故障安全、发布回滚或显著工作量。局部写法、命名及微小偏好不进入采访。
- P0 为不可逆数据/协议、架构阻塞、一致性或重大线上风险；P1 为重要边界、恢复、迁移发布或验证路径；P2 仅保留有实质维护影响者。
- 每轮按依赖讨论 1–3 项，无新高价值缺口即停止。正文只用“实现事项”，每项一个连续分块，包含问题、必要依据、最多三个不同方案和推荐；仅保留未决、延期或待回写事项，不另建摘要。
- **跨边界通信合同硬限制：** 涉及跨实体、线程、进程或 Server/Client 通信时，按 [通信合同](references/通信合同.md) 核查真实路径；内部路由、方法存在不能证明客户端可见或可调用。

## 协作与更新

- **人工协作**：用户可调整阶段、确认与回写节奏；沿用已有授权。继续不等于确认或验证通过，缺口、假设、待补项与复核点留在当前文档，不另建审批文件。
- **结构性变更**：范围、状态、合同、数据权威、依赖或配置真源改变时，同步实际受影响的上下游、客户端合同和 `00`，不扩散到无关分支。
- **文档更新**：默认同轮更新剩余问题或待回写结论，删除旧方案、失效项并告知路径；集中回写时保留并交接未落盘内容。
- 技术结论压成 `01` 的关键约束，仅留影响实现的合同语义、必要理由，沿用被引用编号。列明位置与影响，已有确认及授权直接回写，否则保留待回写要点并请求确认；回读核对语义无损并更新引用后删除 `03` 对应内容，不搬运调查过程、矩阵或证据罗列。
- 产品规则回写 `01`，产品问题留 `02`；上游未决时只留最小阻塞引用，解决后删除，不长期复制上游。

## 完成条件

无未决 P0/P1、待回写结论或上游修订阻塞，关键技术结论已无损压缩至 `01`，核心边界、数据、合同、失败与兼容明确，发布回滚重大风险已有归属，关键验证方式足以证明实现正确，才可标记 `已收敛`。核对一致性，更新状态、计数与日期；无剩余事项时仅保留顶部元信息。重读确认落盘，回复路径及能否进入 `04`，不追加摘要或编码。
