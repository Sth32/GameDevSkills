# 数据与消息拓扑

## 数据

- 区分权威持久化、权威非持久化、镜像、可重建缓存和派生值；每项关键数据明确权威者、写入责任、存盘位置、恢复、同步、未就绪行为和客户端可见性。
- 默认仅权威者持久化跨重启事实，镜像可重建且不成为第二写源；项目已有双写/灾备/快照机制时注明一致性责任。
- 起服顺序：权威恢复 → 镜像全量同步 → ready → 开放依赖入口。权威写成功后发布增量；未 ready 时拒绝、等待或回源，不用默认值判断业务状态。
- 客户端视图须指向真实权威来源与全量/增量通道；内部 Host/View 寻址不等于客户端可见，不建立新的服务端权威。

## 消息

对每个实际触发点记录：当前实体/线程、已有数据、缺失数据及权威者、镜像/RPC/回源方式、下一实体、请求/回包、目标缺失/未就绪/超时行为。骨架只验证技术路由到达权威实体，不实现产品条件。

将配置待接入项区分为本阶段结构接线与后续业务消费；记录真实代码入口与承接阶段。业务规则移交只引用需求，不复制正文。
