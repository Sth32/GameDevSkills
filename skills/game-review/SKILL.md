# 交叉评审游戏功能

先读 [文档位置](references/文档位置.md) 和 [评审范围与门禁](references/评审范围与门禁.md)，固定仓库、分支、基线、目标提交及范围；用 [交叉评审模板](references/交叉评审模板.md) 维护唯一报告。

- 单线或整体评审：`07-交叉评审.md`；分支：`<Uxx>-07-<主题>-交叉评审.md`。Reviewer 输出仅作临时输入，修复复审仍更新原报告。
- **独立 Review 硬限制：** 当前 Uxx 及真实依赖满足条件即可评审，不等待无依赖兄弟；通过 `00-工作流索引.md` 定位共享/祖先需求与实际阶段链。
- **整体 Review 硬限制：** 目标叶单元分别评审后才按集成风险决定；复用有效分支证据，只查组合缺口、冲突和代码漂移。无集成风险在 `00` 标记“不需要”，不补建整体报告。

## 评审与复核

开始评审前读 [独立评审方法](references/独立评审方法.md)。默认由需求、架构正确性、集成运行三个独立视角检查，首轮不读其他 reviewer 结论，再交叉证伪候选；意见数量不是证据。

只报告有现实触发路径、具体位置和影响、未被反证且值得修复的问题；过滤偏好，同根因合并。证实后同轮写入原报告。

- S0：阻断；S1：必须修复；S2：建议修复；S3：记录。
- S0/S1 必须有处理结论。修复后默认由非原作者复核触发路径和回归证据。
- 上游错误先记录根因、归属、影响及拟修改内容；已有授权直接回写。需要重拆范围时按范围参考中的拆分规则处理。

## 协作与完成

- **人工协作**：用户可调整阶段、reviewer 数量或回写节奏，沿用已有授权。缺口、假设、待补项和复核点留在当前报告，不新增审批文档；继续不等于验证通过。
- **文档更新**：默认同轮原位替换失效结论并告知路径；集中回写时交接说明未落盘内容。
- **结构性变更**：范围、状态、合同、数据权威、依赖或配置真源变化时同步真实受影响的上下游、客户端合同和 `00`，只使受影响 Review 失效。
- **一致性**：结束前核对报告与当前基线、证据及实际覆盖。仅完成单人初审、部分检查或延期交叉复核时保持 `评审中`，不虚构独立评审。

完整评审结论：无未解决 S0/S1 且关键证据充分为 `通过`；无 S0、少量 S1 有明确且获接受的处置条件为 `有条件通过`；其余为 `不通过`。写回顶部状态和日期、重新读取确认落盘后交付。`00` 的当前阶段/文档指向本单元 Review；整体评审使用整体 Review 指针。
