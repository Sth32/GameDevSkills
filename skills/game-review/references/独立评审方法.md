# 独立评审方法

协调者给出固定材料与范围，不预先给结论。默认分工：

| 视角 | 重点 |
|---|---|
| 需求 | 当前共享/专属需求是否满足；整体时检查覆盖缺口、重复实现与冲突 |
| 架构正确性 | 数据所有权、状态机、不变量、并发、幂等、事务、失败与补偿 |
| 集成运行 | 配置/导表、协议/客户端合同、兼容/迁移、启动、回滚、日志与测试 |

高风险才增加反作弊、性能或客户端协议视角。各 reviewer 首轮独立读材料；候选记录级别、Uxx/shared 归属、位置、触发场景、违反的规则、影响、修复方向、置信度与未确认事实。

首轮后由另一 reviewer 查代码/测试反证并构造最小路径，区分实际缺陷、文档/测试缺口与偏好，校准级别、合并根因。单 reviewer 也须主动寻找反证，并记录缺少的独立复核。

分支集成特别检查共同写入同一事实、DAG 依赖是否在运行时成立、共享上游变化是否被吸收、合同重名/语义冲突。发现归属 owning Uxx 或 shared；修复复核记录实际执行者与证据。
