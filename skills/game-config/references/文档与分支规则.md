# 文档与分支规则

## 位置

- 从目标项目根目录解析，目标不明先澄清；不取技能目录或任意当前目录。
- 先用已有文档、引用或 `00` 找到同功能目录并续写；跨天和改配置不另建。权威目录归属不明先澄清；明确要求迁移才移动并更新引用。
- 新建根目录按“本次指定 → 项目 `.game-dev-workbench.json` 的 `documentRoot` → `Workbench`”选择。文件/字段缺失用默认值；字段须为非空相对路径字符串，所需配置无效时说明并停止依赖它的新建写入，不静默回退。
- 新目录为 `<文档根目录>/<YYMMDD><功能名>/`，取首次建档的用户当地日期，不增分类或 Uxx 子目录。指定功能路径或带日期目录名原样使用，不重复拼接。
- 只在执行技能时按需读配置，不自动创建或改写，不读环境变量/个人配置，不写入 AGENTS.md。旧文件按实际引用续写，明确要求统一旧名才重命名并更新引用。

## 分支

- 单线使用 `04-配置规划.md`；分支使用 `Uxx-04-<主题>-配置规划.md`，编号至少两位补零。策划说明分别为 `04-策划配表说明.md` / `Uxx-04-<主题>-策划配表说明.md`，均在同一功能目录。
- 独立配置、阻塞和后续实现的范围才拆分，不因多个表而拆分。先更新 `00-工作流索引.md`，分配新稳定 Uxx；父 `04` 只留共同基线、标记 `已拆分`，专属事实移至子文档，共享事实引用不复制，父单元不再进 `05`。
- `00` 仅存 ID、范围、依赖、当前阶段/文档与整体 Review 指针；仅路由变化时更新，不复制配置状态或验证，也不把策划说明当当前文档。
- 开始/恢复时由 `00` 定位当前 Uxx 的共享基线、自身/祖先需求和直接前驱；索引有歧义先修正。只读真实依赖状态与证据，不等待无依赖兄弟；有缺口按入口人工协作规则继续。
