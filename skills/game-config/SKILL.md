# 规划并修改游戏配置

开始前读取 [文档与分支规则](references/文档与分支规则.md)，定位当前单元实际依赖的 `01`–`03`；正常要求 `01=整理完成`、`02/03=已收敛`。用 [配置规划模板](references/配置规划模板.md) 维护唯一 `04-配置规划.md`，不另建执行清单或验证报告。

## 配置边界

- 按职责而非扩展名分类：只改已授权的真实声明式源；Schema 变化单独确认，生成物从真源再生。运行时注册/映射、加载器、生成器和业务逻辑留作后续代码依赖。类别不明时先读 [配置源识别指南](references/配置源识别指南.md)。
- Excel 手动/自动沿用本次已有选择，没有则询问；手动只暂停 Excel，继续其他已授权源。自动编辑保留公式、格式、验证和合并单元格。
- 先收敛真源、字段/引用、ID 业务域与合法范围、校验及消费方式。最终 ID/数值不影响 Schema、查找/引用、加载、控制流、协议或测试成立条件时交策划后配，不追问也不编造；需要配置才能生成、加载或测试时，验证安全默认/占位并注明非最终值。影响实现契约的项仍阻塞，不能伪装为策划收尾。
- 按逻辑对象聚合其物理源，在同一事项写契约、参照对象及变化字段、执行/人工步骤、当前结果、验证和后续代码依赖，不复制完整表或日志。

## 执行与收尾

1. 简单单源改值直接修改并做受影响验证，不审计整套管线。跨源、Schema、多目标或复杂引用时读取 [复杂配置管线指南](references/复杂配置管线指南.md)；设计验证范围时读取 [配置校验清单](references/配置校验清单.md)。
2. 执行已授权配置修改与必要生成，验证真实消费路径；缺少代码接线记入所属事项，注明 `game-scaffold` / `game-implement` 接管，不顺手实现。已误改代码时立即停止，按 [误改代码处置](references/误改代码处置.md) 处理。
3. 收尾时有非阻塞配表提醒或主体配置需策划维护，才按 [策划配表说明模板](references/策划配表说明模板.md) 生成一份交付物；它不是过程文档或配置权威，不滚动维护第二套事实。
4. 检查一致性：契约、授权修改、必要验证和实现所依赖配置均已收敛，待人工项已闭环；可延后值的合法域与安全默认已验证。叶文档写 `已完成`，更新计数和日期，再读取确认落盘。代码依赖留在事项，不用 `待代码接入` 替代顶部状态；当前叶单元可独立进入 `05`。

## 协作与更新

- **人工协作**：用户可调整阶段、确认及回写节奏；沿用已有授权。继续不等于验证通过，缺口、假设、待补项与复核点留在当前文档。
- **分支工作流硬限制：** 按用户确认的方案拆分真实独立范围；当前单元只检查实际依赖，无依赖兄弟不阻塞。拆分/续接按上述参考维护 `00-工作流索引.md`。
- **文档更新**：默认同轮原位替换旧状态、删除失效步骤并告知路径；集中回写时交接未落盘内容。
- **结构性变更**：范围、状态、合同、数据权威、依赖或配置真源变化时，同步实际受影响的上下游、客户端合同、策划说明及 `00`。修订上游先列影响与拟修改内容，已有授权直接回写。
