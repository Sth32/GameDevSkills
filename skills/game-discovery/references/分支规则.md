# 分支规则

- 先从 `00-工作流索引.md` 定位当前 Uxx、共享及自身/祖先需求、实际前驱和阶段文档；无法唯一定位时先修正索引，不靠聊天猜测。没有共享事实不补建单一 `01`，已拆分父文档只作共享基线，不强改回叶终态。
- 只核对真实依赖的状态与证据；无依赖兄弟不阻塞当前单元进入下一阶段、客户端对接或 `Uxx-07` Review。
- 已确认结论按范围回写：共享结论写共享 `01`，专属结论写本单元 `Uxx-01-<主题>-原始需求.md`；缺少时新建并引用适用共享基线，不复制共享正文。
- 仅按用户明确要求或已确认的方案拆分独立范围，不主动提议；同一闭环的小步骤不拆 Uxx。
- 拆分先更新 `00`，给后继分配新稳定 Uxx，不复用 ID，也不以 `U01.1` 编码拓扑。父文档保留共享基线并标记 `已拆分`，专属内容移入子文档；共享内容只引用。父单元停止推进，仅叶单元继续。
- 分支文件为 `<Uxx>-02-<主题>-需求挖掘.md`，编号至少两位补零，与其他过程文档同目录。
- `00` 仅存 ID、范围、依赖、当前阶段/文档及整体 Review 指针。只在这些路由变化时更新，不复制阶段状态、问题、计数或结论；每个单元每阶段仅一份权威文档。
