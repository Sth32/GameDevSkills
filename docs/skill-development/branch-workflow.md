# 分支工作流规范

所有过程文件使用[已解析的功能目录](design.md#文档位置)；命名见[权威文档模型](design.md#权威文档模型)。以下门禁服从[人工协作规则](design.md#人工协作)，继续决定不改变真实状态。

## 边界与身份

- 简单需求单线，不创建 `00` 或 Uxx。真实独立的需求、推进、阻塞、对接或 Review 范围才拆分；同一闭环的连续步骤用阶段内 Step。
- `01` 起即可拆分，后续阶段、对接或 Review 修复时也可继续拆分，不要求先完成整体 `01`。
- Uxx 是稳定身份，至少两位补零，不编码父子/先后、不复用旧 ID。串行、并行与多前驱关系统一写入 `00-工作流索引.md`。

## 创建或继续拆分

优先最短依赖模型；用户要求拆分时直接执行，否则说明理由、范围和依赖后确认，已有授权不重复询问。

1. 创建或更新 `00`，分配新 Uxx 和对应阶段文档。
2. 分支专属事实移到子文档，共享事实只留在父文档供引用；没有共享事实不补建共享 `01`。
3. 父文档标记 `已拆分` 并停止直接推进，由叶单元继续；该状态不代表子单元完成。

需求权威为本单元适用的共享基线及自身/祖先需求文档。叶 `01` 达到 `整理完成` 且真实依赖满足后即可进入 `02`，不等待无依赖兄弟。

## `00-工作流索引.md`

首次分支创建，模板如下：

```markdown
# <功能名>：工作流索引

> 首次分支来源：<阶段文档或 ROOT>
> 整体 Review：未评估 / 不需要 / `07-交叉评审.md`
> 最后更新：<YYYY-MM-DD>

| 单元 | 范围 | 依赖 | 当前阶段 | 当前文档 |
|---|---|---|---|---|
| U01 | <范围> | ROOT | 01 | `U01-01-...md` |
| U02 | <范围> | ROOT | 03 | `U02-03-...md` |
| U03 | <范围> | U01,U02 | 05 | `U03-05-...md` |
```

`ROOT` 指首次拆分前共享基线；继续拆分的子单元依赖父单元。索引只记路由，不复制业务事实或顶部状态；推进须读实际文档。进入 Review 后，当前阶段和文档指向 `Uxx-07`。

## 分支阶段门禁

只检查本单元适用的共享基线、自身/祖先需求、直接前驱及当前阶段所需上游。多前驱须达到所需稳定状态，无依赖兄弟可在任意阶段。结构性变化只使实际受影响的下游和 Review 失效。

## 分支 Review

1. 定位本单元需求、实际 `02`–`06` 链路、代码/配置 diff 和客户端对接文档；自身及真实依赖达到 pre-review 终态即可进入 `Uxx-07-<主题>-交叉评审.md`，不等待兄弟或要求重新合并。
2. 上游问题回写所属单元或真实依赖；修复后原位更新当前 Review。
3. 需继续拆分时暂停受影响 Review，回到最早合适阶段创建子 Uxx。新叶单元各自 Review，父 Review 只留有效共享结论。

## 客户端对接

本单元服务端合同稳定到足以对接即可创建 `Uxx-06-<主题>-客户端对接文档.md`；`06` 只用于排序。共享合同引用共同基线，各分支只写新增或变化合同。

## 整体 Review

所有本次目标叶单元通过各自 Review 后，必须评估组合风险：共享代码/数据权威、状态机、配置表、RPC/事件、客户端合同或迁移/发布顺序。有风险则使用整体 `07-交叉评审.md`，否则在 `00` 写 `整体 Review：不需要`。

输入为分支 Review 结论、对接文档、适用需求基线及当前组合代码、配置、生成物和测试证据。只查需求覆盖、跨分支冲突、合同矛盾、依赖/时序和 Review 后漂移，复用已覆盖内部证据。

问题回到所属 Uxx 或新独立 Uxx，只使受影响 Review 失效；修复后更新分支 Review，再检查受影响的整体结论。
