# Skills 长期准则

这里只维护长期取舍；机制见[流程设计](design.md)和[多分支规范](branch-workflow.md)。

1. **按真实边界拆分**：简单需求单线；独立推进、阻塞、对接或 Review 的范围优先用 Uxx，05、06 仅在用户提出时分 Step。ID 表达身份，`00` 表达依赖。
2. **唯一当前真相**：一个单元一个阶段一份权威文档；事实及时原位更新，跨文档引用，历史交给 Git。
3. **事实自己查，决策才问人**：可从代码、配置和证据回答的问题不转嫁给用户。
4. **按真实依赖推进和传播**：修正错误上游，只影响实际依赖；兄弟分支不互相阻塞，整体 Review 仅由集成风险触发。
5. **验证真实消费链**：配置、实现和对接结论须落到真实消费链与验证证据；Agent 验证不等于完整游戏验收，未覆盖客户端或多人行为须给出 QA 样例。
6. **运行安全优先**：未完成功能可受控关闭，不得破坏启动、资产、数据或其他系统。
7. **按现实风险处理边界**：低影响可恢复问题不为理论完备扩张；高后果问题不因低概率忽略。旁路问题另行处理。
8. **保留合理变化点**：允许规则独立变化所需的局部冗余，避免错误抽象；先查明异常结构的历史、兼容和事故约束再清理。
9. **Review 只阻止有现实影响的问题**：Finding 要有可达性和当前处理价值，偏好不冒充缺陷。
10. **人工决定节奏**：默认连续完成框架、实现与 Agent Review 后交用户；05、06 不强求人工 Review 或跑测。已有授权不重复确认，推进不等于验证通过或获得额外操作权限。
11. **项目配置按需读取**：只在相关技能执行时加载；位置变化不自动迁移已有文档。
