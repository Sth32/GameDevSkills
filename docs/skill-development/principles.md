# Skills 长期准则

这里只维护影响长期设计、开发与维护取舍的短规则。机制和例子见 [流程设计](design.md) 与 [多分支规范](branch-workflow.md)。

1. **简单路径零成本**：没有真实拆分就保持单线，不创建额外工作流结构。
2. **按真实边界拆分**：能独立推进、阻塞、对接或 Review 的范围才创建 Uxx；同一闭环内用 Step。
3. **一个单元一个阶段一份权威文档**：不维护并行真相，相关事实引用而不复制。
4. **ID 与拓扑解耦**：Uxx 表达稳定身份，依赖由 `00` 表达，分支不增加目录层级。
5. **文档保存当前真相**：历史交给 Git；可靠事实及时落盘，不只留在聊天。
6. **事实自己查，决策才问人**：代码、配置与证据能回答的问题不转嫁给用户。
7. **根因优先于补丁**：发现错误上游时修正原决策，变更只传播到真实受影响范围。
8. **按真实依赖推进**：无依赖兄弟不互相阻塞，整体 Review 只由集成风险触发。
9. **证据优于结论**：配置、实现、对接和 Review 必须落到真实消费链与验证证据。
10. **运行安全优先**：不完整功能可受控关闭，但不得破坏启动、资产、数据和其他系统。
11. **边界处理按现实风险付费**：低影响可恢复问题不为理论完备增加复杂度，高后果或不可恢复问题不能仅凭低概率忽略。
12. **旁路问题不扩张主任务**：不影响当前验收的问题简短报告，另行处理。
13. **Agent 验证不等于完整游戏验收**：明确客户端表现、多玩家交互等未覆盖边界，并给出必要的 QA 样例。
14. **保留合理变化点**：规则可能独立变化时允许局部冗余，避免错误抽象和大量模式参数。
15. **异常结构先解释再清理**：查明历史、兼容和事故约束，不因“不优雅”消除未解释差异。
16. **Review 只阻止值得阻止的问题**：Finding 要有现实可达性、明确影响与当前处理价值，偏好不冒充缺陷。
17. **人工决定协作节奏**：默认检查点可调整，已有授权不重复确认；继续决定、验证结论与实际操作权限分别处理。

18. **项目配置按需读取**：技能设置只在使用相关技能时加载；目录变更不自动迁移已有权威文档。
