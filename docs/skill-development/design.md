# Skills 设计文档

技能职责与默认顺序见 [README](../../README.md)，长期取舍见[准则](principles.md)。本文件定义共用协议；工作单元机制见[多分支规范](branch-workflow.md)。每个技能包须包含自身执行所需规则，入口可指定何时读取随包参考文件，不依赖其他技能安装或生成同步脚本。

## 文档位置

1. 使用目标项目根目录，不取技能安装目录或任意当前目录；目标不明确时先澄清。仅执行相关技能时解析配置，不向 AGENTS.md 注入设置。
2. 按已提供文档、阶段引用、`00` 或项目内同功能文档查找已有目录；后续阶段、分支、Review、对接和配表说明都续写原目录。多个候选权威目录无法判定时澄清，不另建第三份。
3. 仅新建时按“本次指定 → 根目录 `.game-dev-workbench.json` 的 `documentRoot` → `Workbench`”选根目录。配置文件或字段缺失用默认值；字段必须是非空相对路径字符串，需读取的 JSON 或字段无效时说明并停止依赖它的新建写入，不静默回退。
4. 功能目录为 `<文档根目录>/<YYMMDD><功能名>/`，日期取首次建档的用户当地日期，不增加分类或 Uxx 子目录。直接指定功能路径或带日期目录名时原样使用，不重复拼接。
5. 只支持项目配置与对话指定；不读取环境变量、个人配置或多层配置，不自动创建或改写配置。团队自定义文件可提交 Git。
6. 跨天或修改配置不另建、重命名或迁移已有功能。明确要求迁移时才移动并更新真实引用，保持唯一权威位置。
7. 长期文档优先更新已有同主题文件；否则在当前功能目录创建 `08-功能实现文档.md`。只有功能目录也不存在才按上述规则新建；明确指定长期文档文件时使用该文件。

## 权威文档模型

每个“工作单元 × 阶段”一份权威文档，保留当前事实、未决项、证据和下一动作。新结论原位替换，相关事实引用而不复制。

`01` 仅保留已确认需求与关键约束，语义无损、文字最少；配置与技术 spec 分别在 `04/05` 展开。`02/03` 的结论压缩回写，核对落盘与语义并更新引用后删除对应内容，不搬运过程、矩阵与证据罗列；未决、延期、待移交或待回写项保留。无剩余事项时仅保留顶部状态、日期和基线等元信息。

| 产物 | 单线 | 分支 |
|---|---|---|
| 阶段文档 | `<阶段号>-<阶段名>.md` | `<Uxx>-<阶段号>-<主题>-<阶段名>.md` |
| 策划配表说明 | `04-策划配表说明.md` | `<Uxx>-04-<主题>-策划配表说明.md` |
| 客户端对接 | `<主题>-客户端对接文档.md` | `<Uxx>-06-<主题>-客户端对接文档.md` |
| 单元 Review | `07-交叉评审.md` | `<Uxx>-07-<主题>-交叉评审.md` |
| 整体 Review | 单线已覆盖 | 按需 `07-交叉评审.md` |
| 工作流索引 | 不创建 | `00-工作流索引.md` |
| 长期功能文档 | `08-功能实现文档.md` | 同一功能一份，不按 Uxx 拆分 |

编号至少两位补零；用户选择的 Step 留在阶段文档内。对接 `06` 和长期文档 `08` 只用于排序，不新增门禁。旧文件按 `00` 与实际引用续写；明确要求统一旧名时才同目录重命名并更新引用。

## 阶段状态与衔接

阶段文档顶部是唯一状态来源；开始前读取实际依赖的状态与证据。默认可移交终态如下：

| 阶段 | 终态 |
|---|---|
| 01 | 叶文档 `整理完成`；共享父文档可为 `已拆分` |
| 02、03 | `已收敛` |
| 04 | `已完成` |
| 05 | `骨架已完成` |
| 06 | `已完成` |
| 07 | `通过`；明确接受所列条件后可按 `有条件通过` 继续 |

结束前核对元信息、正文、验证与下一动作，更新真实终态并重新读取确认落盘；证据不足保留缺口。仅缺 `05/06` 目标环境运行证据时，保留待验证状态并继续可做的实现或评审，不要求用户先跑测；实际安全问题或未决核心设计先处理，不虚报完成或通过。对接以合同充分性和真实可达性为依据，长期文档以稳定契约和最后核对版本为依据，不另造阶段终态。

## 人工协作

默认在已有授权内连续完成 05 框架、06 实现、07 Agent 交叉评审及修复复核后统一交付，用户可做最终 Review 或跳过。05、06 不强求人工确认或跑测；用户参与阶段内 Review 时，按[分支与分步规则](branch-workflow.md#创建或继续拆分)控制单次审阅量。

用户可跳步、合并确认、按假设先行、延后 Review 或集中回写；沿用已有授权，范围、风险或假设实质变化时再沟通。继续决定不替代实际权限，也不等于确认或验证通过。

有缺口时在当前文档记明继续范围、依据/假设、待补项和复核点，不新增审批文档或状态。单 reviewer、人工或延后 Review 如实说明覆盖；提前写长期文档只整理已验证稳定事实，Review 限制写在交接说明或过程文档，不写入长期文档。

## 文档更新与变更传播

新事实默认同轮原位回写并告知路径；集中回写按约定，交接说明未落盘内容。修正上游前列明影响和拟修改内容，已有授权直接回写，超出授权再确认。

范围、状态、合同、数据权威、依赖或配置真源变化时，核对当前元信息、正文、证据、阻塞与下一动作，同步实际受影响的上下游、客户端合同及 `00` 路由/Review 指针；仅使受影响 Review 失效，未传播完成时说明缺口。

## 配置、对接与 Review

配置执行、人工填表步骤和验证结果只以当前 `04` 为准；策划配表说明是按需交付物。对接在本单元合同稳定时即可开始，共享合同引用共同基线。分支及整体 Review 的触发、输入和修复路由见[多分支规范](branch-workflow.md)。

## 长期功能文档

以当前实现、相关分支及必要整体 Review 为依据，按最终系统语义组织职责、稳定规则、数据权威和跨模块合同，注明最后核对版本。不复制 Uxx 拓扑、阶段状态、配置快照、待办或过程历史。

## 验证

[README](../../README.md#规范与验证) 列出本地命令。静态校验检查元信息、包内引用、核心规则与文档链接；检查器测试不代表 `evals/` 行为场景通过。Actions 只读校验，不生成提交。
